# Cashfolio Component Catalogue

Browse shared components, inspect app screens, and try their important states
without connecting to a database.

## Find an Example

- **Components** follows shared UI responsibilities: Controls, Navigation,
  Layout, Grid, Gain and Loss, Confirmation Dialogs, Account Editors, and
  Transaction Editors and Actions.
- **Screens** follows app areas. Route-specific controls stay with their screen;
  for example, find the account switcher under Ledger.
- Open a component's **Docs** entry for its purpose, supported props, and
  examples. Open an individual story to use **Controls** and inspect
  interactions.
- Overview and default examples appear first. Other groups are alphabetical.

## Reveal Regression Scenarios

The sidebar filter excludes the **regression** tag initially. Open the tag
filter next to sidebar search and clear that exclusion to reveal smoke tests,
navigation lifecycles, implementation comparisons, and multi-step mutation
scenarios. These stories continue to run in CI even when excluded from browsing.

Visible interaction demonstrations can also perform actions automatically. A
**Pending** example intentionally keeps its submission busy until you remount
it. Use Storybook's remount control to reset the example.

## Compare Environments

- **Theme** switches Mantine and AG Grid between light and dark.
- **Locale** uses the app's supported user locales, with en-US as the default.
- **Viewport** provides Desktop (1280 × 900), Tablet (768 × 1024), and Mobile
  (390 × 844). Responsive examples can also be resized manually.
- Stories explicitly labelled Light/Dark or with a locale override keep that
  environment. Their descriptions identify the override. Fixed viewport stories
  retain their requested size; use an unpinned example for free comparison.
- Controls and typing share the value in input playgrounds. Complex screen
  fixtures have Controls disabled; interact with the rendered screen instead.

## Code Ownership

Sidebar groups describe how to find examples; they do not move application code.
Shared UI stays under `src/components/<responsibility>/`, and route-owned UI
stays with its route. Accounts and Categories screens also use the shared
`account-management` and `hierarchy-organize` modules.
